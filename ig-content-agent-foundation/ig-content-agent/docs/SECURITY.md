**Status key:** Done = exists in the scaffold today. Planned = a task will deliver it (task id given). N/A = does not apply yet, with the trigger that makes it apply.

## Project-specific risks

**Instagram access token.** It can publish as the owner. Store it server-side only, redact it from logs and error output, refresh before expiry, and keep the app secret out of any client-side code. If it leaks: revoke it in the Meta developer dashboard, generate a new one, and confirm nothing is in git history.

**Public media URL.** Instagram downloads the video from a public URL, so anyone with the link can view it while it exists. Use random unguessable keys, expire the link after publishing (or after a short time), and delete the temporary copy.

**Publishing without approval.** The state machine, the approval hash check, and the publisher's own re-check make this fail even if a route is buggy. It is covered by tests (TEST_PLAN, "Approval").

**Command injection through FFmpeg.** Subprocess calls use argument lists; file paths are generated by the app; user text (captions, titles) is never placed in a command line without going through FFmpeg's text-file input.

**Prompt injection.** Web pages, Swishy pages, uploaded files and LLM output are data. They cannot approve, publish, change settings, or override `RULES.md`.

**Unofficial Instagram tools.** Password-login libraries and scraping are banned (ADR-002): they put the account at risk of restriction.

**Dependencies.** Pin versions, review new packages before adding, run `pip-audit` (or equivalent) before release.

## Public routes

Only these may be reachable without login: the login page, static assets, and a health check that returns no data. Anything else is a bug.

## Before every commit and deploy

```bash
python scripts/security_preflight.py
```

## Incident checklist (leaked secret)

1. Revoke the secret at its source.
2. Generate a new one and update `.env` only.
3. Remove it from git history if it was committed, and re-run the pre-flight.
4. Record what happened in `docs/DECISIONS.md`.
